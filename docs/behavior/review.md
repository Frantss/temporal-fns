# Gherkin suite review

Reviewed against the API proposal, public declarations, source code as evidence of current behavior, and decisions D01–D07. Only files under `docs/behavior/` were changed. This review does not execute the library's tests or certify implementation conformance.

All 56 public functions remain represented: 54 root functions and both calendar adapters. The suite now contains 247 scenario/outline definitions in 16 feature files, expanding to 1,621 formulated cases. The 560 function/input-kind combinations remain intact. Counts describe formulations, not passing tests.

## Implementation discrepancy retained for future work

`eachMonthOfInterval` for PlainYearMonth endpoints `-271821-04` and `-271821-05` must emit both months under D07. Native Node 26.12.1 throws when adding a month to the first endpoint. The native algorithm selects a reference day before adding, which can require an unavailable complete date. See [Temporal's year-month addition algorithm](https://tc39.es/proposal-temporal/#sec-temporal-adddurationtoyearmonth).

The [current sequence](../../src/collections.ts) calls native addition and catches a `RangeError` by terminating iteration. For this input, that path returns only April. This conclusion comes from native arithmetic probes and reading the source; the library's test suite was not run. The implementation and its tests are unchanged.

D04 still requires an error for an unavailable required PlainDate period boundary. D07 requires a complete sequence when the PlainYearMonth outputs themselves are representable. Stopping after a speculative step that is already beyond the interval end is a separate, permitted behavior. The suite now states those distinctions explicitly.

## Expectation checks

Calendar arithmetic spot checks covered the existing custom week/year numbers, month-grid counts, leap-year anniversary totals and large duration field fixture. The new calendar duration limits were checked against the [native duration validity rule](https://tc39.es/proposal-temporal/#sec-temporal-isvalidduration): absolute years/months/weeks must be below 2³². The scenarios include both the last accepted value and the first rejected value.

The native lower-bound month-addition failure was treated as evidence requiring a behavior decision, not automatic authority to weaken an expectation. D07 resolves that decision. No other incorrect numeric result was found in the spot-checked examples; this is not a claim that every concrete outcome was executed.

The apparent tension between “zero distance has no suffix” and a rounded zero is resolved by the existing direction rule: equality of the actual values suppresses the suffix. A nonzero future or past difference retains its direction even when its displayed magnitude rounds to zero. REL-029 distinguishes those inputs explicitly.
