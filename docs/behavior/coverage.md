# API behavior coverage

The draft covers **56 functions** across **16 feature files**, with **247 scenario/scenario-outline definitions**. Expanding each Examples row and counting each ordinary scenario once gives **1621 formulated cases**. This is a documentation count, not executed or passing tests. Quantified relationships inside individual scenarios are not multiplied into that count.

The type-contract matrix contains **560 function/input-kind combinations**: all 56 functions against eight main Temporal kinds, legacy Date, and string. For pattern parsers, the varied argument is the reference; for duration parsers, it is the primary text argument. The matrix therefore does not imply that duration parsers accept Duration objects.

Every function has behavior-specific examples beyond the shared matrix and purity contracts. The table lists up to three representative case IDs per function; the linked file contains its remaining rules and examples. All functions also participate in `case-CON-008` for input/global ownership. Accepted and rejected type combinations are `case-TYPE-001` and `case-TYPE-002`.

## Validation and limits

See [review.md](review.md) for corrected specification gaps and the known implementation discrepancy for `case-SEQ-027`. The agreed full API is represented; this is not a claim that the implementation satisfies every scenario.

- Reconciled all 54 root exports and both calendar exports against the per-function map.
- Checked stable case-ID uniqueness, source-tag resolution, all 560 type-matrix entries, Examples-table widths, placeholder bindings, and action/assertion presence.
- Manually reviewed Gherkin structure and expected outcomes against their sources. No Gherkin parser is installed in this workspace, so official parser validation has not been performed.
- The seven discovery decisions are accepted; acceptance of this whole draft remains separate.
- Existing implementation, tests, manifests, dependencies, and the original API proposal remain unchanged. No system tests were run and no step definitions or runner integration were added.

The suite covers the entire public API and its documented rules. It does not claim every possible input combination, identical Intl/time-zone data on every host, or semantics for the deliberately unspecified details in [discovery.md](discovery.md).
